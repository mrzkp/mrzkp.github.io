Image Warping and Mosaicing

Overview

Given two or more photographs, I aim to create an image mosaic by registering, projective warping, resampling, and compositing them. To accomplish this, I compute homographies to warp images.

Key techniques implemented: Homography estimation using SVD, inverse warping with bilinear interpolation, image rectification, multi-resolution blending using distance transforms, Harris corner detection with ANMS, feature descriptor extraction, KD-tree matching with Lowe's ratio test, RANSAC for robust fitting.

Recover Homographies

Before warping the images into alignment, I must first recover the parameters of the transformation between each pair of images.

We want to recover a projective transformation such that

\[ \begin{bmatrix} a & b & c \\ d & e & f \\ g & h & 1 \end{bmatrix} \begin{bmatrix} x \\ y \\ 1 \end{bmatrix} = \begin{bmatrix} wx' \\ wy' \\ w \end{bmatrix} \]

Notice that if we expand this out, then we have the following system of equations:

\[ \begin{cases} ax + by + c = wx' \\ dx + ey + f = wy' \\ gx + hy + 1 = w \end{cases} \implies \begin{cases} ax + by + c = (gx + hy + 1)x' \\ dx + ey + f = (gx + hy + 1)y' \end{cases} \implies \begin{cases} ax + by + c - gxx' - hyx' = x' \\ dx + ey + f - gxy' - hyy' = y' \end{cases} \]

Which we can finally transform to...

\[ \implies \begin{bmatrix} x & y & 1 & 0 & 0 & 0 & -xx' & -yx' \\ 0 & 0 & 0 & x & y & 1 & -xy' & -yy' \end{bmatrix} \begin{bmatrix} a \\ b \\ c \\ d \\ e \\ f \\ g \\ h \end{bmatrix} = \begin{bmatrix} x' \\ y' \end{bmatrix} \]

Thus, given some n amount of correspondence points, I can stack these equations to form a 2n * 9 matrix A. For each correspondence point (x, y) -> (x', y'), I formulate two equations:

x'(h31x + h32y + h33) = h11x + h12y + h13

y'(h31x + h32y + h33) = h21x + h22y + h23

These equations are what is used to construct A.

Afterwards, I use SVD on A to solve for AH = b to construct H, which is the homography matrix.

Blending Images to Create Mosaics

Using the warping function, I can construct a mosaic between warped and original images (even warped to warped images if desired).

The process goes as follows... Compute Homography Matrix H between correspondence points from both images and choose either image (in this case, the first one, though both work). Given this image and H, I then apply warping. During the warping process, I also specifically constructed output based on the warped image to help in creating the width and height of the final mosaic, as well as accommodating for any translations. Afterwards, I place the warped image on the left and the unaltered second image on the right. Finally, to ensure clean results, I apply some blending techniques. The only difference is, I have to accommodate for an irregular mask here. I can construct one by creating binary masks of both images on where there are pixels located and computing the distance transform on each of these masks to create weights for each image. The lowest frequency component is then blended using weights computed from distance transforms. For the higher frequency, I use a binary to select between the two images based on which is closer at each pixel.

Previously, correspondence points were selected manually, which was time-consuming. Now, I automate this process!

For this, I use another set of images.

This is accomplished by the following: (1) Detecting corners from an image. (2) Extracting feature descriptors from the images given the corners. (3) Matching these descriptors to the images. (4) Using RANSAC to compute a homography. (5) Using what I built earlier to warp the images together.

Detecting Corner Features in an Image

Below is a naive Harris corner detection on the left. On the right, I implemented ANMS to select the points. The ANMS looks good due to the high amount of points that are available in the image, and how well-defined the corners are. For reference, there are 500 points on the right that are outputted.

To accomplish this, I implement the Adaptive Non-Maximal Suppression (ANMS) process. First, I sort the corner points based on their Harris response strength. For each corner point xi, I find all points that have a strength greater than 0.9 times the response strength of xi. This helps identify stronger points in the vicinity. Next, I calculate the minimum distance from xi to these stronger points, which is designated as the point's "suppression radius." Finally, I select the top 500 points with the largest suppression radii.

Extracting a Feature Descriptor for each Feature Point

From the ANMS points, I iterate through each one and extract a square patch of size (40x40). To ensure noise doesn't play an effect, I apply a Gaussian Blur.

For each of the patches, I can resize it to a 8x8 descriptor. Finally I vectorize and normalize it.

This is done because even though there are these points, I want to gain some 'feature' from them for matching, which is the next section!

Feature Matching

Afterwards, I can now use these descriptors to start matching features with one another, which I can use to create correspondences. This means repeating the above process twice.

For each image, I iterate through each feature of the image and match it to whatever is the best matching feature of the other image. I utilize KDTrees for this for efficient querying.

Afterwards, I ensure that a match in one direction is also the best match in the other direction. If not, then I do not include it.

To ensure highest quality, I also utilized Lowe's ratio test, which I used to compare the closest and second-closest feature matches. If it is the case that these distances are too close to one another, then I consider the match unreliable.

RANSAC

Some matches can be misleading, hence why I utilize RANSAC to further reduce the number of outliers, since outliers can greatly change the output.

I randomly select 4 pairs of points, then I compute the homography matrix given these points. During this process, I construct a list of inliers from this homography matrix.

For each point in an image, I determine the other images warped position by using the homography. Then, using the literal position of the point of the other image and determine if the distance between the estimated point from the homography matrix and the original point vs the actual point from the other image is less than some error (this is to ensure robustness). If it is the case, then I add it to the list of inliers.

After some predetermined amount of iterations (500 in my case), I use the homography that constructed the most amount of inliers.
